# «Поиграй с Марком»: первый уровень

## Запуск

Node >=22.13; `npm ci`, `npm run dev`. На главном экране нажать «На аэродром» в карточке «Поиграй с Марком». В развёрнутом приложении сохраняется существующий вход в семейный кабинет. При недоступном API действует прежний локальный режим.

Управление: WASD или стрелки, Shift — бег, пробел — прыжок, E — поднять/установить, Q — вернуть переносимую деталь на исходную площадку. На сенсорном экране доступны кнопки направлений и действия. Возле центральной окружности переносимая деталь устанавливается в свой слот. Пять завершённых деталей открывают следующие пять. После двадцатой детали доступна кнопка взлёта. Полёт можно повторять.

## Архитектура

- Next.js 16.3.4, React 19, TypeScript, существующий Three.js 0.185.1; новых зависимостей в приложении нет.
- `app/play-mark/PlayMark.tsx`: интерфейс, жизненный цикл, связь с существующим состоянием Home.
- `app/play-mark/engine.ts`: сцена, управление, подбор, перенос, установка, камера, полёт, освобождение WebGL-ресурсов.
- `app/play-mark/models.ts`: процедурный аэродром, двадцать моделей деталей и персонаж с шарнирными конечностями.
- `lib/play-mark/state.ts`: этапы, доступность деталей, миграция и подсчёт награды; проверяется без WebGL.
- `Saved.assembly` проходит существующие localStorage, экспорт/импорт, `useSync` и JSON payload семейного API. Схема сервера уже допускает новые поля payload; миграция SQL не нужна. Старые сохранения получают пустую сборку.
- Одна звезда за каждую новую деталь, десять за сборку целиком. Сумма — 30. Повторный полёт не увеличивает награду. Никаких запросов к ИИ и озвученных пояснений.

## Внешность: незавершённая часть

Пользователь предоставил утверждённый лист персонажа. Процедурный образ обновлён по повседневному варианту: светлые волосы с отдельными прядями, белое поло с воротником и молнией, тёмно-синие брюки, горчичные кроссовки, голубые глаза и улыбка. Это упрощённая геометрическая интерпретация; портретное сходство не подтверждено. Исходный лист не включён в публичный репозиторий. Ходьба, бег, перенос и посадка анимированы через шарниры. Это не импортированный GLB, не скиннинг и не готовая художественная модель Марка.

Для финальной внешности нужны исходные изображения и отдельный rigged/skinned GLB с проверенными анимациями idle/walk/run/carry/seated. Заменять процедурный персонаж следует через контракт `markModel()` (root, hands, pose), сохранив игровую механику.

## Проверки

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.

Проверки нового состояния охватывают четыре этапа, произвольный порядок внутри этапа, блокировку будущих деталей, повторную установку, максимум награды, старые/повреждённые сохранения, экспорт/импорт и доступность всех площадок.

Для выпуска дополнительно проверить реальный семейный API с двумя профилями и двумя устройствами: локально нет настроенной базы/почты production. Также необходима проверка на реальных iPhone/Android, художественная замена персонажа и дальнейшая полировка моделей самолёта. Второй уровень пока не реализован.

Браузерная проверка Chrome прошла: все 20 деталей подобраны и перенесены реальными клавишами, четыре этапа завершены, после первой детали выполнена перезагрузка, показаны 30 звёзд и финальный полёт, проверены повторный полёт и выход/вход без повторной награды. Ошибок JavaScript нет. На ширине 390 px проверены сцена, пауза/продолжение и выход. В отдельном тесте с имитацией API проверена отправка частичной сборки через существующий revision-based PUT с сохранением прежних звёзд и миссий. Это не заменяет тест production-базы и реальных устройств.
