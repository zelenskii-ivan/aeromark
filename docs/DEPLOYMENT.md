# Развёртывание Аэромарка

## Требования

- Ubuntu 24.04 LTS
- 2–4 vCPU, 4–8 ГБ RAM, 80 ГБ NVMe
- Docker Engine и Docker Compose
- домен с A-записью на IP сервера

## Подтверждение почты

Открытая регистрация требует рабочего отправителя писем:

1. добавить домен в Resend;
2. подтвердить DNS-записи SPF и DKIM;
3. указать в `.env` ключ `RESEND_API_KEY`;
4. указать `EMAIL_FROM`, например `Аэромарк <noreply@aeromark.ru>`.

В локальной разработке без этих переменных ссылка подтверждения выводится
только в журнал API. В production фиктивная отправка отключена.

## Первый запуск

1. Клонируйте репозиторий на сервер.
2. `cp .env.example .env` и заполните все значения.
   Пароль базы и административный токен: `openssl rand -base64 32`.
   `DOMAIN` — домен без схемы, `APP_ORIGIN` — полный HTTPS-адрес сайта.
3. `docker compose up -d --build`
4. Проверьте `https://ваш-домен/health` — должно вернуться `{"ok":true}`.

Caddy автоматически выпустит и обновит TLS-сертификат. PostgreSQL хранится в
отдельном Docker volume. До открытия регистрации настройте ежедневную
зашифрованную резервную копию базы вне сервера.

Наружу открыты только 80 и 443: `web`, `api` и `postgres` объявлены через
`expose`, а не `ports`, и доступны лишь внутри сети compose.

## Миграции базы

SQL-файлы лежат в `server/sql` и применяются при старте API по возрастанию
имени. Применённые записываются в таблицу `schema_migrations`, на время
применения берётся `pg_advisory_lock`, поэтому одновременный старт нескольких
экземпляров безопасен. Новая миграция — новый файл со следующим номером; уже
применённые файлы менять нельзя.

`003_password_reset.sql` переименовывает `email_verification_tokens` в
`email_tokens` и добавляет колонку `purpose`: одна таблица обслуживает и
подтверждение почты, и смену пароля.

## Восстановление пароля

`POST /api/auth/forgot-password` присылает ссылку на `/?reset_password=…`.
Ссылка живёт час, срабатывает один раз, живая ссылка на семью ровно одна:
новое письмо гасит предыдущее. Смена пароля удаляет все сессии семьи — тот,
кто увёл аккаунт, не остаётся в нём после «восстановления».

Ответ на запрос одинаков для существующего и выдуманного адреса, поэтому по
этой форме нельзя проверить, кто здесь зарегистрирован. По той же причине
регистрация на занятый адрес отвечает как на свободный, а письмо «аккаунт уже
существует» уходит владельцу адреса.

## Проверка регистрации

После запуска откройте главную страницу, зарегистрируйте взрослого и проверьте
получение письма. Ссылка подтверждения должна вести на домен приложения и после
открытия автоматически создавать защищённую серверную сессию.

Семью можно заблокировать через `POST /api/admin/families/:id/block` — все её
активные сессии будут удалены. Административный токен не передаётся в браузер.

## Синхронизация

Сайт и API живут на одном домене: Caddy отдаёт `/api/*` и `/health` на
`api:4000`, остальное — на `web:3000`. Поэтому фронтенд обращается к API по
относительному пути и никакой настройки от родителя не требует. Если сервер
не поднят, приложение работает как локальная PWA, а во вкладке «Для взрослого»
честно пишет, что сервер недоступен.

## Удаление данных

- `DELETE /api/children/:id` — профиль ребёнка вместе с прогрессом и PIN.
- `DELETE /api/me` — вся семья, все дети и все сессии.

## Обновление

```bash
git pull --ff-only
docker compose up -d --build
docker compose ps
```

Перед обновлением production сначала сделайте резервную копию PostgreSQL.

## Резервная копия

```bash
docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" \
  | gzip | age -r "$AGE_RECIPIENT" > aeromark-$(date +%F).sql.gz.age
```

Проверяйте восстановление копии на отдельной машине хотя бы раз в квартал:
непроверенная резервная копия не считается резервной копией.
